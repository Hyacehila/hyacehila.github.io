带情感的语音合成和音色迁移是智能 NPC 的一部分；虚拟偶像和大面积铺开的 NPC 可能需要不同的技术路线

流程图 NLU NLG 可能需要和 LLM 混合使用，但是如何混合，自生成和预生成应该如何协同，这是值得思考的问题。

或许可以考虑打破第四面墙？ 如果是一个智能 NPC 的话。

情感陪伴，写信交流可能是一个很好的信息交流方法，包括相关的留白也可能成为信的内容的一些思考，能够去带来定制信息，考虑玩家本身游戏内和游戏外的内容，尝试去解除第四面墙。

可能需要先在容错度较高的场景使用，大批量生成一定会有少量离谱的效果。 AI 很难接管游戏本身的核心逻辑 Runtime，如果允许介入数值（如好感度），发放奖励，涉及影响游戏内玩法的地方，需要非常谨慎的考虑。

对于网游而言，成本是不可忽视的问题，预生成和实时生成都是需要考虑的，或者说延时生成。 另一个问题则是生成的风险，我们可能需要单独的门禁模型来拦截各种不应该输出的内容。如果有异步延时生成的话也是可以考虑的，林离的写信也是很好的结局方案，此时还可以检测用于的输入内容看看是否存在破甲，因为时效要求更低了。

局内的陪玩，像人一样的玩游戏
语音和文本闲聊，长期记忆，辅助的外挂能力（这个取决于游戏内的本身的玩法可能涉及的不同的方案，往往是一些附加功能，取决于策划需求）
自定义：服装 语音 人设

特殊：对 No Action 也作为一种特殊的 Action，而不是只识别系统认为有价值的 Action，这就是留白，游戏内的静止和游戏外的静止都是一种信号，也要给出符合人设的反馈

可能的技术架构和知识注入的层级，参考成熟的 LLM Agent 架构

四层的知识
1. Soul ： AI 是谁，人设，音色
2. User：玩家本身的用户画像与偏好
3. Memory：更懂 AI 和玩家之间的交流，玩家在游戏内的行为
4. Skill ，准确说是对行为体系本身的描述和约束，而不是 Agent Skill（移动，互动，摄影，引导建议，社交行为）  而将模糊的自然语言命令转换为传统引擎能够处理的行为，是一个需要考虑和优化的问题，暴露什么，如何串联工具来实现意图的映射以及底层的执行，需要桥接。

工具层：
1. 游戏内知识查询，方便 QA
2. 地图搜索
3. 获取位置信息
4. 音乐推荐

最后 AI 要进入游戏客户端，实现行为

对话模型可以考虑和行为模型分类，让行为 LLM 决定行为和工具（这样才是可以更好的去构建实时模型，参考 JD 的那一个，来判断语音本身是否结束了，语音模型有很多的开源实现），让 Chat 模型专注自然语言的生成。

语言模型为了保证风格，大概率需要做新的训练，去结合场景本身，合成数据，校验质量，构造超长对话，这都是可能需要考虑的问题。 正常情况下应该只需要 SFT 和适当的 DPO 对于人格扮演这里就足够， SFT 提供能力，DPO 做一些危险的拒绝回答和过滤。 Training 的时候可能需要混合一些common 数据，避免灾难性遗忘。

用户画像，事实，对话摘要；根据时间和记忆召回考虑整个系统的遗忘。 

这是一个复合的 Agent 系统，我们有一个确定的目标，但是至于如何到达这个架构的设计，还需要进一步的思考。技术和相关功能的策划需要一起实现。

陪伴带来的最好的效果可能是低活跃用户的活跃，如果陪伴本身是目的。
