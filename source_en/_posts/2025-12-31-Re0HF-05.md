<h2>1. GRPO Trainer Parsing</h2>
<h3>1.1 The rationale for GRPOTrainer</h3>
<p>GRPOTrainer carries training in GRPO algorithms; it is more straightforward to see its working mechanisms and to debug and optimize.</p>
<h4>1.1.1 Full training cycle</h4>
<p><strong>GRPO Trainer One Step Training Process</strong></p>
<p><strong>Input</strong>1 bats prompts (e. g. watch size=2)</p>
<p><strong>Step 1: Online Sampling</strong></p>
<ul>
<li>For each prompt: Generate k=4 different responses (using current policy model π)</li>
<li>Result: 2 prompts x 4 results = 8 sound Reactions</li>
</ul>
<p><strong>Example:</strong></p>
<ul>
<li><p><strong>Prompt 1</strong>：&quot;Calculate 5+3&quot;</p>
<ul>
<li>Response 1.1: &quot;5+3=8&quot;</li>
<li>Response 1.2: &quot;First five plus three is eight, the answer is eight.&quot;</li>
<li>Response 1.3: &quot;Counted 8&quot;</li>
<li>Response 1.4: &quot;Result is 8&quot;</li>
</ul>
</li>
<li><p><strong>Prompt 2</strong>：&quot;Calculation 7-2&quot;</p>
<ul>
<li>Response 2.1: &quot;7-2=5&quot;</li>
<li>Response 2.2: &quot;Seven minus two equals five.&quot;</li>
<li>Response 2.3: &quot;The answer is five.&quot;</li>
<li>Response 2.4: &quot;Calculated result 5&quot;</li>
</ul>
</li>
</ul>
<p><strong>Step 2: Assessment of awards</strong></p>
<ul>
<li>Call <code>reward_function(prompts, responses)</code></li>
</ul>
<p><strong>Example reward:</strong></p>
<ul>
<li>Prompt 1 award: [0.5, 0.9, 0.6, 0.4]</li>
<li>Prompt 2 awards: [0.7, 0.8, 0.5, 0.6]</li>
</ul>
<p><strong>Step 3: Compute group comparative advantage (Group Relative Advantage)</strong></p>
<p>Response group for each prompt:</p>
<ul>
<li><p><strong>Prompt 1</strong>：</p>
<ul>
<li><code>mean_reward_1 = (0.5+0.9+0.6+0.4)/4 = 0.6</code></li>
<li><code>advantages_1 = [0.5-0.6, 0.9-0.6, 0.6-0.6, 0.4-0.6] = [-0.1, +0.3, 0.0, -0.2]</code></li>
</ul>
</li>
<li><p><strong>Prompt 2</strong>：</p>
<ul>
<li><code>mean_reward_2 = (0.7+0.8+0.5+0.6)/4 = 0.65</code></li>
<li><code>advantages_2 = [+0.05, +0.15, -0.15, -0.05]</code></li>
</ul>
</li>
</ul>
<p><strong>Step 4: Calculate strategic loss (Policy Los)</strong></p>
<ul>
<li>For each (response, advantage):<ul>
<li><code>log_prob = log π_θ(response | prompt)</code></li>
<li><code>policy_loss += -advantage * log_prob</code></li>
</ul>
</li>
</ul>
<p><strong>Understanding:</strong></p>
<ul>
<li><code>advantage &gt; 0</code> ~ Increase the probability of generating the response</li>
<li><code>advantage &lt; 0</code> • Reduce the probability of generating the response</li>
</ul>
<p><strong>Step 5: KL Regularization</strong></p>
<ul>
<li>Calculates the KL diffusion of the current model and the reference model:<code>kl_penalty = β * KL(π_θ || π_ref)</code></li>
<li>Effect: limit the excessive deviation of the model from the reference model</li>
</ul>
<p><strong>Step 6: Total losses and reverse transmission</strong></p>
<ul>
<li><code>total_loss = policy_loss + kl_penalty</code></li>
<li><code>total_loss.backward()</code></li>
<li><code>optimizer.step()</code></li>
</ul>
<p><strong>Step 7: Update reference models (optional)</strong></p>
<ul>
<li>Some of the EMAs that will regularly update the reference model as the current model</li>
</ul>
<h4>1.1.2 The mathematical rationale for the comparative advantage of the cluster</h4>
<p><strong>Traditional PPO issues</strong>：</p>
<ul>
<li>Value network estimated status value required</li>
<li>Additional training value network required (costed)</li>
<li>Value estimates may not be accurate (impacting training stability)</li>
<li>Complicated</li>
</ul>
<p><strong>GRPO Innovation</strong>:
No value networks needed! Use the group comparative advantage</p>
<p>Generate k responses for each programpt:<code>{r_1, r_2, ..., r_k}</code></p>
<p><strong>Advantage estimate</strong>：</p>
<p>For each prompt generation &#36;k&#36; A response. &#36;{a_1, a_2, ..., a_k}&#36;, the advantage function is defined as:</p>
<p>&#36;&#36;
A(s, a_i) = R(s, a_i) - \text{mean}(R(s, \cdot))
&#36;&#36;</p>
<p><strong>of which</strong>：</p>
<ul>
<li>&#36;R(s, a_i)&#36;: Response &#36;i&#36; ♪ The prize ♪</li>
<li>&#36;\text{mean}(R(s, \cdot))&#36;: Average incentive for all responses from the same group</li>
</ul>
<p><strong>Intuition.</strong>：</p>
<ul>
<li>&quot;How much better is this response than the other responses from the same group?&quot;</li>
<li>I don't need to know.&quot;Absolutely.&quot;Standards</li>
<li>Just the relative ranking.</li>
<li>Use group average as baseline</li>
</ul>
<p><strong>Mathematics certificate (simplified)</strong>：</p>
<p>&#36;&#36;
\begin{aligned}
\mathbb{E}[A(s,a)] &amp;= \mathbb{E}[R(s,a) - \text{mean}(R(s,\cdot))] \
                  &amp;= \mathbb{E}[R(s,a)] - \mathbb{E}[\text{mean}(R(s,\cdot))] \
                  &amp;= \mathbb{E}[R(s,a)] - \mathbb{E}[R(s,a)] \
                  &amp;= 0
\end{aligned}
&#36;&#36;</p>
<ul>
<li>The advantage function is zero average.</li>
<li>Reduced variance and increased training stability</li>
</ul>
<p><strong>Why does it work?</strong></p>
<ol>
<li>Automaticization: different incentive scales for prompt, and comparative advantage eliminates this problem</li>
<li>Reduction of the variance: relative stability compared to absolute assessment</li>
<li>Value-free network: substantial simplification achieved</li>
<li>Adaptive: auto-adaptation to different difficult tasks</li>
</ol>

<h4>1.1.4 Role of reference models</h4>
<p><strong>Reference Model</strong>：</p>
<ul>
<li>Usually a copy of the SFT model before training.</li>
<li>Parameters frozen, not involved in training</li>
<li>Effect: Calculate KL dispersion to prevent model deviations too far</li>
</ul>
<p><strong>Why do you need reference models?</strong></p>
<p><strong>Problem: Over-optimization</strong>
If only incentives are optimized, models may:</p>
<ol>
<li>Generate strange, unnatural text</li>
<li>Use incentive function leaks (reward hacking)</li>
<li>Knowledge acquired during loss of pre-training</li>
<li>The same function as the reference model in the DPO, and the same is true of the parameters involved</li>
</ol>
<p><strong>Beta (kl coef) controls balance</strong>：</p>
<ul>
<li>Beta, big, big, more conservative, near reference model.</li>
<li>Beta, little twig, more radical models, higher rewards.</li>
</ul>
<p><strong>Actual</strong>:
GRPTrainer automatically creates reference models:</p>
<ol>
<li>Parameters for copying the current model</li>
<li>Freeze parameters (requires grad=False)</li>
<li>For KL only</li>
</ol>
<p><strong>Monitoring indicators</strong>：</p>
<ul>
<li><code>objective/kl</code>: KL diffusion value with ideal range 0.1~5.0</li>
<li>Too small (&lt;0.1: Models are almost non-updated</li>
<li>Too big.&gt;10: Models are too far away, potentially unstable</li>
</ul>

<h3>1.3 Detailed key parameters</h3>
<h4>Parameter 1: Num generations</h4>
<p><strong>num_generations</strong>Number of responses per programpt</p>
<p><strong>Impact</strong>：</p>
<ul>
<li>Training signal stability (larger and more stable)</li>
<li>Costing (larger and more expensive)</li>
<li>Quality of strength estimates (larger and more accurate)</li>
</ul>
<p><strong>Recommended value</strong>：</p>
<ul>
<li><code>num_generations = 4-8</code>(Standard)</li>
<li><code>num_generations = 2-4</code>(Quick Experiment)</li>
<li><code>num_generations = 8-16</code>(Quality training)</li>
</ul>
<p><strong>Attention.</strong>：</p>
<ul>
<li>Actual <code>batch_size = per_device_batch_size * num_generations</code></li>
<li>Need to consider the obvious limitations</li>
</ul>
<h4>Parameter 2: temperature</h4>
<p><strong>temperature</strong>: Sample temperature, control diversity of generation</p>
<p><strong>Impact</strong>：</p>
<ul>
<li>high (e. 1.0): Generate more samples and explore more possibilities but may have lower quality</li>
<li>Low (e.g. 0.5): Generate more certainty, use known good models, but may lack exploration</li>
</ul>
<p><strong>Recommended value</strong>：</p>
<ul>
<li><code>temperature = 0.7-0.9</code>(Standard)</li>
<li><code>temperature = 0.5-0.7</code>(Conservative, quality first)</li>
<li><code>temperature = 0.9-1.2</code>(radical, exploration priority)</li>
</ul>
<p><strong>Adjustment Policy</strong>：</p>
<ul>
<li>Initial training: higher temperatures (exploration)</li>
<li>Post-training: lower temperature (utilisation)</li>
</ul>
<h4>Parameter 3: kl coef</h4>
<p><strong>kl_coef</strong>KL RPV, beta similar to DPO</p>
<p><strong>Role</strong>：</p>
<ul>
<li>Limiting excessive deviations from reference models</li>
<li><code>KL(π_θ || π_ref)</code> • Punishment</li>
</ul>
<p><strong>Impact</strong>：</p>
<ul>
<li>kl coef Large (e.g. 0.1): The model is more conservative, the improvement is slow but stable</li>
<li>kl coef Small (e.g. 0.01): Models are more radical, improve fast but potentially unstable</li>
</ul>
<p><strong>Recommended value</strong>：</p>
<ul>
<li><code>kl_coef = 0.05</code>(Standard)</li>
<li><code>kl_coef = 0.01-0.03</code>(radical)</li>
<li><code>kl_coef = 0.1-0.2</code>(Conservative)</li>
</ul>
<p><strong>Monitor</strong>：</p>
<ul>
<li><code>objective/kl</code> Should be kept in &lt; 10</li>
<li>If KL is too big, add kl coef</li>
</ul>

<h3>2.2 Training phase analysis</h3>
<p><strong>Typical training curve</strong>：</p>
<p><strong>Phase 1: Rapid improvement period</strong>（Step 0-500）</p>
<ul>
<li><code>rewards/mean</code>：0.2 → 0.5 → 0.7</li>
<li>The phenomenon: modeled basic model of rapid learning</li>
</ul>
<p><strong>Phase 2: Steady upgradation period</strong>(Step 500 to 2000)</p>
<ul>
<li><code>rewards/mean</code>：0.7 → 0.8 → 0.85</li>
<li>Event: Model optimization details</li>
</ul>
<p><strong>Phase 3: Depression period</strong>（Step 2000+）</p>
<ul>
<li><code>rewards/mean</code>：0.85 → 0.87 → 0.88</li>
<li>Symptoms: slow improvement, near ceiling</li>
</ul>
<p><strong>Warning signal</strong>：</p>
<ul>
<li><code>rewards/mean</code> Check for reward functions or learning rates</li>
<li><code>objective/kl</code> Too big.&gt;20) Increase <code>kl_coef</code></li>
<li><code>loss</code> No contraction, no reduction in learning rates.</li>
</ul>
<h3>2.3 Common problems and solutions</h3>
<p><strong>Problem 1: Average incentive does not rise</strong></p>
<p><strong>Possible cause</strong>：</p>
<ol>
<li>Inappropriate design of reward functions (all responses are equal)</li>
<li>Over- or over-leaving</li>
<li><code>num_generations</code> Too small.</li>
<li>The temperature is not set properly.</li>
</ol>
<p><strong>Solutions</strong>：</p>
<ul>
<li>Check reward function: Ensure differentiation degrees</li>
<li>Adjusting the learning rate: trying <code>5e-7</code> or <code>2e-6</code></li>
<li>Increase <code>num_generations</code> To 8</li>
<li>Adjustment <code>temperature</code> to 0.8-1.0</li>
</ul>
<p><strong>Problem 2: KL spent a lot of time</strong></p>
<p><strong>phenomena</strong>：<code>objective/kl &gt; 20</code></p>
<p><strong>Reason</strong>: Model deviation from reference model too far</p>
<p><strong>Solutions</strong>：</p>
<ul>
<li>Increase <code>kl_coef</code>(if from) <code>0.05</code> → <code>0.1</code>）</li>
<li>Reduced learning rate</li>
<li>Reduction in number of training steps</li>
</ul>
<p><strong>Issue 3: Discretionary deficiencies</strong></p>
<p>GRPO notable occupancy ≈ base model + num generations x watch size</p>
<p><strong>Solutions</strong>：</p>
<ul>
<li>Decrease <code>num_generations</code>（8 → 4）</li>
<li>Decrease <code>per_device_train_batch_size</code>（2 → 1）</li>
<li>Enable <code>gradient_checkpointing</code></li>
<li>Quantify with 4-bit</li>
<li>Decrease <code>max_new_tokens</code></li>
</ul>
<p><strong>Question 4: Slow training</strong></p>
<p><strong>GRPO reason for being slower than SFT/DPO</strong>：</p>
<ol>
<li>Need to generate an online response</li>
<li>Calculate incentive function required</li>
<li>Generate multiple response increases</li>
</ol>
<p><strong>Accelerated programme</strong>：</p>
<ul>
<li>Enable Flash Attention</li>
<li>Use <code>bf16</code> Mixed precision</li>
<li>Optimizing incentive function calculations</li>
<li>Use less <code>num_generations</code></li>
</ul>

<p><strong>Common problems</strong></p>
