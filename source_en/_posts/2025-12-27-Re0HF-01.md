<h2>2. Core concept of oversight fine-tuning (SFT)</h2>
<h3>2.1 What's SFT?</h3>
<p><strong>Supervised Fine-Tuning, SFT</strong> It is a process of training models with labeled data.</p>
<p>In the context of the dialogue mandate, our data are usually as follows:</p>
<p><strong>Example of dialogue:</strong></p>
<ul>
<li><strong>User</strong>: Please help me summarize the content of this conversation...</li>
<li><strong>Assistant</strong>: This conversation focused on...</li>
</ul>
<h3>2.2 Los Masking: SFT core</h3>
<p>Attention. <strong>This is the most important concept of this chapter!</strong></p>
<p>In training, the model needs to predict the next token. But the question is:</p>
<ul>
<li>Models should learn.<strong>Generate Answers</strong>, not learning.<strong>Generate problem</strong></li>
<li>If you calculate the whole sequence, Los, the model will try to&quot;Reread&quot;User problems</li>
</ul>
<p><strong>Solutions: Losing Masking</strong></p>
<table>
<thead>
<tr>
<th>Enter Sequence</th>
<th>[User questions]</th>
<th>[Adviser Answers]</th>
</tr>
</thead>
<tbody><tr>
<td>Tab</td>
<td>[-100]</td>
<td>[actual token]</td>
</tr>
<tr>
<td>Los Calculator</td>
<td>[No] No calculation</td>
<td>[Yes] Calculate</td>
</tr>
</tbody></table>
<ul>
<li><code>labels = -100</code> This is where it is.<strong>Do not calculate, Loss</strong>(Default Ignored value for PyTorch)</li>
<li>Only part of the assistant's answer will be used for training.</li>
</ul>
<h3>2.3 Loss Masking in code</h3>
<p>Yes. <code>trainer.py</code> Yes. <code>process_func()</code> function:</p>
<pre><code class="language-python"># 1. 初始化所有 labels 为 -100（全部忽略）
labels = [-100] * len(input_ids)

# 2. 计算 prompt 长度
prompt_len = len(prompt_ids)

# 3. 只有 prompt 之后的部分设置为实际的 token ID
labels[prompt_len:] = input_ids[prompt_len:]
</code></pre>
<p><strong>Effects</strong>：</p>
<ul>
<li>User problem segment:<code>labels = [-100, -100, -100, ...]</code> ♪ No count, Loss ♪</li>
<li>The assistant answers the section:<code>labels = [token1, token2, token3, ...]</code> → Calculating Los</li>
</ul>

<h4>Why do you need so much?</h4>
<ol>
<li><p><strong>Gradients cannot be quantified!</strong></p>
<ul>
<li>Gradient for updating parameters, FP16/FP32 accuracy must be maintained</li>
<li>If the gradient is 4-bit, the re-engineering of the parameters will be seriously distorted and the model will not be able to contain</li>
</ul>
</li>
<li><p><strong>Optimizer state cannot be quantified!</strong></p>
<ul>
<li>AdamW Optimizer requires storage of first-order kinetic (m) and second-stage kinetic (v)</li>
<li>These movements must remain FP32 precisions, otherwise the optimal effects will decline dramatically.</li>
</ul>
</li>
<li><p><strong>A copy of the parameters requires high precision!</strong></p>
<ul>
<li>FP16/FP32 precision is required to calculate the updated parameter</li>
<li>Could not perform numerical operations directly on 4-bit weights</li>
</ul>
</li>
</ol>
<h4>Conclusions</h4>
<blockquote>
<p><strong>Quantification is just a model.&quot;Load&quot;It's easier, but...&quot;Training&quot;Still need a lot of visibility!</strong></p>
<p>To effectively reduce the visibility of training, it is necessary to reduce the number of trainingable parameters.</p>
</blockquote>
<h3>3.3 LoRA（Low-Rank Adaptation）</h3>
<p><strong>Problem</strong>: even after quantification, fine-tuning of all parameters will require significant visibility (as noted above, approximately 100 GB)</p>
<p><strong>Solutions</strong>: only a small part of the parameters is trained</p>

<p>Same 8B model, using LoRA training:</p>

<thead>
<tr>
<th>Component</th>

<p><strong>Conclusions</strong>LoRA reduces the need for visibility from 100 GB to about 10-15 GB (with active value), and normal graphic cards can be trained!</p>
<p><strong>LoRA works well</strong>：</p>
<pre><code>原始模型权重 W（冻结，不训练）
    维度：d × d（例如 4096 × 4096）

LoRA 适配器（可训练）：
    A：d × r（例如 4096 × 64）
    B：r × d（例如 64 × 4096）

最终输出 = W·x + α·(B·A)·x
              ↑        ↑
           原始输出  LoRA调整
</code></pre>
<p><strong>Key points</strong>：</p>
<ul>
<li>Original weight W frozen, not involved in training</li>
<li>Train only two small arrays A and B(r) &lt;&lt; d, normally r = 8, 16, 32, 64)</li>
<li>The result of B.A. is a low-level matrix, which is a primary weight.&quot;Adjustments&quot;</li>
<li>Alpha is a scaling factor, controls the level of impact of LoRA</li>
</ul>
<p><strong>Parameter Volume Comparison</strong>：</p>
<ul>
<li>Original: 4096 x 4096 = 16,777,216 parameters</li>
<li>LoRA: 4096 x 64 + 64 x 4096 = 524,288 Parameters (%)<strong>97% reduction!</strong>）</li>
</ul>
<p>Code configuration:</p>
<pre><code class="language-python">from peft import LoraConfig, get_peft_model

lora_config = LoraConfig(
    r=64,           # LoRA 秩（越大参数越多）
    lora_alpha=16,  # 缩放因子
    target_modules=[&quot;q_proj&quot;, &quot;k_proj&quot;, &quot;v_proj&quot;, &quot;o_proj&quot;],  # 应用到哪些层
    lora_dropout=0.01,
    task_type=&quot;CAUSAL_LM&quot;
)

model = get_peft_model(model, lora_config)
model.print_trainable_parameters()
# 输出：trainable params: 83,886,080 || all params: 8,108,634,112 || trainable%: 1.0346%
</code></pre>
<h2>4. DataCollarator: Data Collator</h2>
<h3>4.1 What's DataColator?</h3>
<p><code>DataCollator</code> It's responsible for combining multiple samples into one of the bats, only filled in an equal length structure.<code>torch</code>The matrix method in place is designed to accelerate training, each of which uses a one-dimensional set of two-dimensional set of tensor, then backward positive transmission, loss calculation and reverse transmission:</p>
<pre><code>样本1: [1, 2, 3, 4]        →  padding  →  [1, 2, 3, 4, 0, 0]
样本2: [5, 6, 7, 8, 9, 10] →  不变    →  [5, 6, 7, 8, 9, 10]
                              ↓
                         组成 batch
</code></pre>
