<h2>2. RLHF vs DPO</h2>
<h3>2.1 Traditional RLHF (PPO) process</h3>
<p><strong>Traditional RLHF (PPO) process</strong></p>
<ol>
<li><strong>Collecting preference data</strong> Human Marker</li>
<li><strong>Training incentive model</strong> • Training in rewarder models with preferred data, which will require the construction of a value model to ensure the stabilization of the gradient in baseline, resulting in significant significant savings</li>
<li><strong>PPO Optimizing Policy</strong> • Sample from the strategy model, rate it with the reward model, update the strategy</li>
</ol>
<p><strong>Four models are required:</strong> Strategies, references, rewards, value models</p>
<p><strong>Question:</strong></p>
<ul>
<li>It's complicated. It takes multiple models.</li>
<li>Training is unstable, and it requires a lot of involvement.</li>
<li>Costed (sampling required)</li>
</ul>
<h3>2.2 DPO: Simplified Preference Alignment</h3>
<p><strong>DPO Process</strong></p>
<ol>
<li><strong>Collecting preference data</strong> → Same as RLHF</li>
<li><strong>Direct Optimization Policy</strong> ← <strong>Major changes</strong></li>
</ol>
<p><strong>Only 2 models:</strong> Policy + Reference Model</p>
<p><strong>Advantages:</strong></p>
<ul>
<li>It's simple, it's easy to achieve.</li>
<li>Training is stable, no complex involvement.</li>
<li>Computer efficiency</li>
<li>The code logic is close to SFT, still to optimize the loss.</li>
</ul>
<h3>2.3 Maths (from intuition to formulae)</h3>
<h4>2.3.1 Core objectives of RLHF</h4>
<p>In the traditional RLHF, our goal is simple:<strong>Make models more likely to produce human preferences.</strong>。</p>
<p>In mathematical terms, for a group of preferences, &#36;(x, y_w, y_l)&#36;(of which) &#36;y_w&#36; It's better to answer that.&#36;y_l&#36; The answer is poor. We want:</p>
<p>&#36;&#36;P(y_w &gt; y_l \mid x) &gt; 0.5&#36;&#36;</p>
<p>That is, the model should think that the answer is better than the answer was given.</p>
<h4>2.3.2 Traditional RLHF practices: training reward models</h4>
<p>To achieve this goal, the traditional RLHF has two steps:</p>
<p><strong>Step 1: Training incentive model &#36;R(x, y)&#36;</strong></p>
<p>The incentive model is designed to score each answer. We train it with preference data, making:</p>
<p>&#36;&#36;R(x, y_w) &gt; R(x, y_l)&#36;&#36;</p>
<p><strong>Step 2: Optimizing strategies with enhanced learning</strong></p>
<p>Adjust policy models using PPO equations &#36;\pi_\theta&#36; the parameters that give it higher rewards for the answers it generates:</p>
<p>&#36;&#36;\text{目标：最大化 } E[R(x, y)]&#36;&#36;</p>
<p><strong>Problem</strong>This requires training in an independent incentive model, complex enhanced learning algorithms, cumbersome and unstable processes.</p>
<h4>2.3.3 Insight of DPO: The reward function can interpret expression</h4>
<p>The main lines of the DPO are:<strong>If we know the best strategy of the incentive function, we can go around the reward model and directly optimize the strategy.</strong></p>
<p><strong>Key Theorem</strong>: The best policy incentive function can be expressed in RLHF settings as:</p>
<p>&#36;&#36;R^<em>(x, y) = \beta \cdot \log\left(\frac{\pi^</em>(y \mid x)}{\pi_{\text{ref&#125;&#125;(y \mid x)}\right) + Z(x)&#36;&#36;</p>
<p>Of which:</p>
<ul>
<li>&#36;\pi^*(y \mid x)&#36; = Best strategy.</li>
<li>&#36;\pi_{\text{ref&#125;&#125;(y \mid x)&#36; = Reference policy (memode after SFT, as starting point)</li>
<li>&#36;\beta&#36; = temperature parameter, control deviation</li>
<li>&#36;Z(x)&#36; = Normalized constant (and &#36;y&#36; Not relevant, negligible when optimising)</li>
</ul>
<p><strong>Intuition.</strong>：</p>
<p>This formula tells us:<strong>The size of the incentive depends on the strategy model versus the reference model.&quot;Preferance Change&quot;</strong>。</p>
<ul>
<li>If &#36;\pi^*&#36; Compare &#36;\pi_{\text{ref&#125;&#125;&#36; More likely to generate an answer → an incentive for the answer High</li>
<li>If &#36;\pi^*&#36; Compare &#36;\pi_{\text{ref&#125;&#125;&#36; And it's less likely to generate a certain answer.</li>
</ul>
<h4>2.3.4 Optimization objectives of the DPO</h4>
<p>With the expression of the reward function, we can write the target for optimization.</p>
<p><strong>Targets for RLHF (with incentive models)</strong>：</p>
<p>&#36;&#36;\mathcal{L}_{\text{RLHF&#125;&#125; = \log \sigma\left(\beta \left[R(x, y_w) - R(x, y_l)\right]\right)&#36;&#36;</p>
<p>of which &#36;\sigma&#36; is the sigmaid function. This loss encourages &#36;R(x, y w) &gt; R(x, y_l)&#36;。</p>
<p><strong>DPO objectives (using a strategy model)</strong>：</p>
<p>Adds the expression of the reward function to the message, and removes it. &#36;Z(x)&#36;, gets:</p>
<p>&#36;&#36;\mathcal{L}<em>{\text{DPO&#125;&#125; = \log \sigma\left(\beta \cdot \log\frac{\pi</em>\theta(y_w \mid x)}{\pi_{\text{ref&#125;&#125;(y_w \mid x)} - \beta \cdot \log\frac{\pi_\theta(y_l \mid x)}{\pi_{\text{ref&#125;&#125;(y_l \mid x)}\right)&#36;&#36;</p>
<p>Simplified:</p>
<p>&#36;&#36;\mathcal{L}<em>{\text{DPO&#125;&#125; = \log \sigma\left(\beta \cdot \log\frac{\pi</em>\theta(y_w \mid x) \cdot \pi_{\text{ref&#125;&#125;(y_l \mid x)}{\pi_\theta(y_l \mid x) \cdot \pi_{\text{ref&#125;&#125;(y_w \mid x)}\right)&#36;&#36;</p>
<p><strong>What's the meaning of this loss?</strong>：</p>
<ul>
<li><strong>Molecular</strong>(What we want):&#36;\pi_\theta(y_w \mid x)&#36; Big.&#36;\pi_{\text{ref&#125;&#125;(y_l \mid x)&#36; It's the benchmark.</li>
<li><strong>Factor</strong>(We're avoiding):&#36;\pi_\theta(y_l \mid x)&#36; Small.&#36;\pi_{\text{ref&#125;&#125;(y_w \mid x)&#36; It's the benchmark.</li>
</ul>
<p>In training, we maximize this loss by increasing the gradient, making:</p>
<ul>
<li>&#36;\pi_\theta(y_w \mid x)&#36; The model is more likely to generate chosen answers than the reference model.</li>
<li>&#36;\pi_\theta(y_l \mid x)&#36; The model is less inclined to generate reprojected answers than the reference model is.</li>
</ul>
<h4>2.3.5 Why reference models?</h4>
<p>You might ask:<strong>Why not just maximize it? &#36;\pi_\theta(y_w \mid x)&#36;Minimize &#36;\pi_\theta(y_l \mid x)&#36;？</strong></p>
<p><strong>Problem</strong>: this will lead to model collapse (Mode Collapse)</p>
<p>If there is no reference model constraint, the model may learn to:</p>
<ul>
<li>High probability of output for chosen (close 1)</li>
<li>Respond to the very low probability of output (close to 0)</li>
</ul>
<p>But it makes the model:</p>
<ul>
<li>Forget the SFT phase.</li>
<li>Generate strange, unnatural answers.</li>
<li>I'm losing my ability to generalize.</li>
</ul>
<p><strong>Role of reference models</strong>：</p>
<p>&#36;\pi_{\text{ref&#125;&#125;&#36; Just like one.&quot;anchor&quot;, ensures that:</p>
<ul>
<li>&#36;\pi_\theta&#36; You can't deviate from the original model at will.</li>
<li>Only adjust the orientation of preferences</li>
<li>Maintaining linguistic capacity and stability of models</li>
</ul>
<p>Maths, that's through. <strong>KL Scatter Normalization</strong>Achieved:</p>
<p>&#36;&#36;\text{KL}(\pi_\theta \Vert \pi_{\text{ref&#125;&#125;) = \sum_y \pi_\theta(y \mid x) \log\frac{\pi_\theta(y \mid x)}{\pi_{\text{ref&#125;&#125;(y \mid x)}&#36;&#36;</p>
<p>The loss function of the DPO already contains the KL binding in a hidden way (by &#36;\beta&#36; Parameter control).</p>

<h3>4.2 Key parameters: Beta</h3>
<p><code>beta</code> is the most important ultra-parameter for the DPO:</p>
<pre><code>beta 的作用：控制模型偏离参考模型的程度

beta 大 (如 0.5):
  └─→ 模型更保守，不敢偏离参考模型太远
  └─→ 适用于：偏好数据噪声较大时

beta 小 (如 0.05):
  └─→ 模型更激进，可能偏离参考模型较远
  └─→ 适用于：偏好数据质量高时

推荐起始值: 0.1
调整范围: 0.05 - 0.5
</code></pre>

<h2>10. Limitations and prospects of the DPO</h2>
<h3>10.1 Limitations of the DPO</h3>
<h4>Dependence on offline data</h4>
<ul>
<li>Precollected preferences only</li>
<li>No online exploration and learning</li>
</ul>
<h4>Incentive function hidden</h4>
<ul>
<li>DPO hides the reward function through mathematical changes</li>
<li>We can't control the reward signal directly.</li>
<li>Difficulty in achieving complex incentive designs</li>
</ul>
<h4>Only for preferences</h4>
<ul>
<li>I can't handle a mission that requires a clear reward signal.</li>
<li>For example: mathematical reasoning, code generation, etc., require valid tasks</li>
</ul>
<h3>10.2 Next: GRPO and verifiable incentives</h3>
<p><strong>Problem</strong>: Can we design better rewards if our mission has a clear correct/mistakeful judgement (e.g., mathematical questions)?</p>
<p><strong>Answer</strong>: Yes! This is where advanced RL methods like GRPO are used.</p>

<p><strong>Appendix: Common problems</strong></p>
<p><strong>Q: DPO has changed the model since training?</strong><br>A:1) Check beta values, which may lead to excessive deviation (2) Check preference data quality (3) Reduce training epochs</p>
<p><strong>Q: Never lifts/accumulations?</strong><br>A:1) Checks for correct data format 2) Attempts to increase learning rate 3) Ensures that chosen is better than reprojected</p>
<p><strong>What if there's not enough to show?</strong><br>A:1) Use <code>ref_model=None</code> Allows the DPOTrainer to autoprocess 2) to reduce the size of the watch size 3) to enable the original checkpointing</p>
