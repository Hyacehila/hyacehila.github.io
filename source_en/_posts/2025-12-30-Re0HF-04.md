<h2>2. GRPO Albula</h2>
<h3>2.1 Core thinking: comparative advantages of clusters</h3>
<p>The previous section addressed “Why GRPO”: DPO cannot directly consume online authentication signals. The next question is how GRPO consumes this signal: it does not give a straight-on-one rating, but rather a set of answers to the same prompt sample and puts each one back in the group for comparison.</p>
<p><strong>Traditional PPO issues</strong>：</p>
<ul>
<li>Need an independent value network (Value Network/Critic) and combine with reward signals to estimate advantages</li>
<li>Training links are heavier, more sensitive to clitic, KL, rollout and watch</li>
</ul>
<p><strong>GRPO Innovation</strong>：</p>
<ul>
<li>Generate for each programpt <strong>k each ring Reactions</strong>(e.g. k=4)</li>
<li>Use group internalization / standardization reward to estimate advantages</li>
<li>No extra value network required</li>
</ul>

<h3>2.2 An optional background: mathematical forms and core differences</h3>
<p>To understand the innovations of GRPO, we need to compare the mathematical forms of PPOs and GRPOs.</p>
<p>If you only want to use GRPOTaire, you can first capture the three conclusions of this section: GRPO does not need critic/ GAE; the advantage comes from a comparison of the group with the same prompt; the same group is updated several times to understand the old-policy ratio, climping and KL/reference constraints. The formula below is designed to help readers put these conclusions back in the PPO context.</p>
<h4>2.2.1 The mathematical form of PPO</h4>
<p><strong>PPO Loss Function (full version):</strong></p>
<p>&#36;&#36;
L_{\text{PPO&#125;&#125;(\theta) = \mathbb{E}_t\left[L_t^{CLIP}(\theta) - c_1 L_t^{VF}(\theta) + c_2 S<a href="s_t">\pi_\theta</a>\right]
&#36;&#36;</p>
<p>Of which:</p>
<p><strong>Strategic losses (CLIP losses)</strong>：
   &#36;&#36;
   L_t^{CLIP}(\theta) = -\min\left(r_t(\theta)\hat{A}_t, \text{clip}(r_t(\theta), 1-\epsilon, 1+\epsilon)\hat{A}_t\right)
   &#36;&#36;</p>
<ul>
<li>&#36;r_t(\theta) = \frac{\pi_\theta(a_t \mid s_t)}{\pi_{\theta_{old&#125;&#125;(a_t \mid s_t)}&#36; ○Softscale sample ratio</li>
<li>&#36;\hat{A}_t&#36; ← Empirical Functions Estimates</li>
<li>&#36;\epsilon&#36; ← Crop parameters (usually 0.2)</li>
</ul>
<p><strong>Value Function Loss</strong>：
   &#36;&#36;
   L_t^{VF}(\theta) = \left(V_\theta(s_t) - V_t^{\text{target&#125;&#125;\right)^2
   &#36;&#36;</p>
<ul>
<li>&#36;V_\theta&#36; • Value network (needs separate training)</li>
<li>&#36;V_t^{\text{target&#125;&#125;&#36; Target value</li>
</ul>
<p><strong>Arsenal Regularization</strong>：
   &#36;&#36;
   S<a href="s_t">\pi_\theta</a> = -\sum_a \pi_\theta(a \mid s_t) \log \pi_\theta(a \mid s_t)
   &#36;&#36;</p>
<p><strong>PPO Advantage Function Calculation (GAE)</strong>：</p>
<p>&#36;&#36;
\hat{A}<em>t^{\text{GAE&#125;&#125;(\gamma, \lambda) = \sum</em>{l=0}^{\infty} (\gamma \lambda)^l \delta_{t+l}^V
&#36;&#36;</p>
<p>of which &#36;\delta_t^V = r_t + \gamma V(s_{t+1}) - V(s_t)&#36; is a trade disability.</p>
<p><strong>Critical observations</strong>：</p>
<ul>
<li>[Facilitation] Need for training<strong>Value Network</strong> &#36;V_\theta&#36;(Additional parameters)</li>
<li>[Facilitation] Need** broad advantages estimate (GAE)** to calculate complex</li>
<li>[Facilitation] Dependence<strong>Sampling ratio of importance</strong> &#36;r_t(\theta)&#36;</li>
<li>[Facilitation] Need for a cut mechanism to prevent over-up</li>
</ul>
<h4>2.2.2 Methodological form of GRPO</h4>
<p><strong>GRPO Loss Function (Intuitive Version)</strong>：</p>
<p>&#36;&#36;
L_{\text{GRPO&#125;&#125;(\theta) = -\mathbb{E}<em>{s \sim \mathcal{D}, a_i \sim \pi</em>\theta(\cdot \mid s)}\left[\hat{A}(s, a_i) \log \pi_\theta(a_i \mid s)\right] + \beta \cdot \text{KL}(\pi_\theta \Vert \pi_{\text{ref&#125;&#125;)
&#36;&#36;</p>
<p><strong>Of which:</strong></p>
<p>This is written in the policy-gradient instinct to see how rewards can enter the update; actual realization requires a specific trainer. Original DeepSeekMath GRPO uses clipped subside and KL; as of 2026-05-05, TRL <code>GRPOTrainer</code> Default <code>beta=0.0</code>、<code>loss_type=&quot;dapo&quot;</code>、<code>scale_rewards=&quot;group&quot;</code>、<code>num_iterations=1</code>,Reference/KL, Loss, reward scaling and multiple rounds of climped update should be used by <code>GRPOConfig</code> Yes.</p>
<p><strong>Group Relative Advantage</strong>：
   &#36;&#36;
   \hat{A}(s, a_i) = \frac{R(s, a_i) - \frac{1}{k}\sum_{j=1}^{k} R(s, a_j)}{\operatorname{std}({R(s, a_j)}_{j=1}^{k}) + \epsilon}
   &#36;&#36;
   If not, it can be understood that:
   &#36;&#36;
   \hat{A}(s, a_i) = R(s, a_i) - \text{mean}(R(s, \cdot))
   &#36;&#36;</p>
<ul>
<li>&#36;R(s, a_i)&#36; ← Reward function or reward signal echo Reactions &#36;a_i&#36; Ratings</li>
<li>&#36;k&#36; Group size (number of responses per programpt)</li>
<li><strong>Chile</strong>: The advantage is<strong>Relative to Group Mean</strong>; above the same group average is positive and below the same group average is negative</li>
</ul>
<p><strong>KL Scatter Normalization</strong>：
   &#36;&#36;
   \text{KL}(\pi_\theta \Vert \pi_{\text{ref&#125;&#125;) = \sum_{a} \pi_\theta(a \mid s) \log \frac{\pi_\theta(a \mid s)}{\pi_{\text{ref&#125;&#125;(a \mid s)}
   &#36;&#36;</p>
<ul>
<li>&#36;\pi_{\text{ref&#125;&#125;&#36; ← Reference Policy (Freezing SFT Model)</li>
<li>&#36;\beta&#36; KL coefficient</li>
<li>It's conceptually binding to limit policy not to be far away from reference; in the realization of DeepSeekMath/ TRL, the common estimation is that &#36;\frac{\pi_{\text{ref&#125;&#125;}{\pi_\theta} - \log \frac{\pi_{\text{ref&#125;&#125;}{\pi_\theta} - 1&#36;, not necessarily the full distribution of the visible number.</li>
</ul>
<p><strong>Critical observations</strong>：</p>
<ul>
<li><strong>No value network required</strong>(savings on visibility and calculation)</li>
<li><strong>No GAE/ Value Network required</strong>(Incentives for direct construction of centralised advantage; std scaling is a common realization option)</li>
<li><strong>Still possible to use old-policy rateo and shear</strong>(The same rollout is particularly important when it is updated several times)</li>
<li><strong>KL / restraint is one of the stability tools</strong>(Concrete concretisation, not as the only mechanism for stabilization)</li>
</ul>
<h4>2.2.3 Core differentiation</h4>
<p>The PPO's advantage estimates usually depend on GAE:</p>
<p>&#36;&#36;
\hat{A_t} = \sum_l(\gamma \lambda)^l \delta_{t+l}^V
&#36;&#36;</p>
<p>GRPO's advantage comes from the group under the same programt.</p>
<p>&#36;&#36;
\hat{A}(s, a_i) = R(s, a_i) - \text{mean}(R)
&#36;&#36;</p>
<p>Common realization also divides the group by std, bringing different prompt reward scales closer.</p>
<ul>
<li><strong>Value Network</strong>:PPO needs &#36;V_\theta&#36;;GRPO does not need extra value head.</li>
<li><strong>Sample Policy</strong>:PPO using rollout and old-policy radio; GRPO online &#36;k&#36; Response, it is still possible to use radio / climping when updating the same rollout several times.</li>
<li><strong>Stability mechanisms</strong>: PPO common combination is radio clipping + KL; GRPO can use radio clipping or can be bound by configuration KL / reference.</li>
<li><strong>Visible occupancy</strong>: PPO is a strategic network + value network + reward signal/ reward model; GRPO is a strategic network + reward signal without additional value network.</li>
</ul>
<h4>2.2.4 Why is the comparative advantage of the cluster effective?</h4>
<p><strong>Math intuition.</strong>：</p>
<p>For each programt &#36;s&#36;, Generate &#36;k&#36; A response. &#36;{a_1, a_2, ..., a_k}&#36;：</p>
<p><strong>Nature of zero average value</strong>：
   &#36;&#36;
   \mathbb{E}<em>{a_i \sim \pi</em>\theta}[\hat{A}(s, a_i)] = \frac{1}{k}\sum_{i=1}^{k} (R(s, a_i) - \text{mean}(R)) = 0
   &#36;&#36;</p>
<ul>
<li>Naturalization of the Advantage Functions</li>
<li>Reduced variance and increased training stability</li>
</ul>
<p><strong>Internalize / Scale</strong>：</p>
<ul>
<li>The incentive scale for different prompts may vary (easiness, difficulty)</li>
<li>Internalization and std scaling helps stabilize training</li>
<li>But it does not guarantee natural comparability across the prompt scale; in TRL <code>scale_rewards</code> Optional <code>group</code>、<code>batch</code> or <code>none</code>, the selection needs to be validated by task and reward distribution</li>
</ul>
<p><strong>No absolute value.</strong>：</p>
<ul>
<li>PPO: &quot;What's the value of this response?&quot; Yes, I do. &#36;V(s)&#36;</li>
<li>GRPO: &quot;How much better is this response than the other responses from the same group?&quot; ♪ Just a group comparison ♪</li>
</ul>
<h3>2.3 Why?&quot;Group relative&quot;？</h3>
<p><strong>Traditional RL</strong>: Need to estimate absolute value,&quot;How's that for a response?&quot; ♪ Need value networks ♪</p>
<p><strong>GRPO</strong>: Just a relative comparison,&quot;Is this better than the other responses from the same team?&quot; → Directly use reward function</p>
<p><strong>Advantages:</strong></p>
<ul>
<li>Simple: no additional network required</li>
<li>Stability: relatively better</li>
<li>Efficiency: reduced training costs</li>
</ul>
<h2>3. Incentive system in GRPO</h2>
<h3>3.1 Incentive signals: core components of enhanced learning</h3>
<p>In GRPO and modern enhanced learning algorithms, what must be provided is that <strong>Reward signal</strong>It's not necessarily a neural network. <strong>Reward model</strong>I'm sorry. This is important: DeepSeek-R1-Zero uses anacity reward + format reward and does not use non-eurolal RM; complete DeepSeek-R1 follow-up RL also adds reward model/ reference reward, and the paper also mentions that the reference reversion was introduced only at the last 400 steps to reduce the risk of rewarding.</p>
<p><strong>What's the reward signal?</strong></p>
<p>The role of the reward signal is to:</p>
<ul>
<li><strong>Input</strong>:prompt + restone (or other information relevant to the task)</li>
<li><strong>Output</strong>: a standard incentive value, which indicates the quality of the response</li>
<li><strong>Form</strong>: A function <code>R(prompt, response, context) → reward</code></li>
</ul>
<p>This function can be achieved in many ways:</p>
<ul>
<li>Rule function or verifier: e.g. answer matching, unit testing, SQL execution results, database finality;</li>
<li>LLM / rubric judge: lets strong models be evaluated by rubric or pairwise comparison;</li>
<li>Neuro-reward models: training a dedicated RM to predict human preferences or mission quality;</li>
<li>Mixed incentives: combine the verifier, judice, RM, costs and safety constraints.</li>
</ul>
<p><strong>Key points</strong>：</p>
<ul>
<li>In GRPO, we optimized the strategy model. &#36;\pi_\theta&#36;</li>
<li>But it needs a reward signal. &#36;R&#36; Tell us what's better in the team's response.</li>
<li>Neural RM is just a realization of the reward signature, not a condition of GRPO</li>
</ul>
<h3>3.2 Two types of training for neuro-reward models</h3>
<p>If you choose to use the reward signal as a nerve RM, the reward model can usually be trained in two ways:</p>
<h4>Modalities 1: Rules-based training</h4>
<p><strong>Apply scene</strong>: Tasks with clear and correct answers (e.g., mathematical questions)</p>
<p><strong>Training process</strong>：</p>
<pre><code class="language-python"># 示例：数学题奖励模型训练
training_data = [
    {
        &quot;prompt&quot;: &quot;计算 2+2&quot;,
        &quot;response&quot;: &quot;答案是 4&quot;,
        &quot;outcome&quot;: +1.0  # 答案正确
    },
    {
        &quot;prompt&quot;: &quot;计算 2+2&quot;,
        &quot;response&quot;: &quot;答案是 5&quot;,
        &quot;outcome&quot;: -1.0  # 答案错误
    },
]

# 训练奖励模型：学习预测 outcome
reward_model.train(
    inputs=[(d[&quot;prompt&quot;], d[&quot;response&quot;]) for d in training_data],
    targets=[d[&quot;outcome&quot;] for d in training_data]
)
</code></pre>
<p><strong>Rationale</strong>：</p>
<ul>
<li>Rule functions (e.g. <code>check_answer_correct()</code>) Generate training labels</li>
<li>Incentive model learning to imitate this rule function</li>
<li>After training, models can be extended to similar problems.</li>
</ul>
<p><strong>Advantages</strong>：</p>
<ul>
<li>[Effects] No manual labelling: rules automatically generate training data</li>
<li>[Effects] Probable: The answer is objective</li>
<li>[Effects] Efficient: A large number of training samples can be generated</li>
</ul>
<p><strong>Limits</strong>：</p>
<ul>
<li>[Facilitation] Need for clear rules for certification</li>
<li>[Facilitative] Only judgmental.&quot;Right and wrong.&quot;Quality assessment difficult</li>
</ul>
<h4>Mode 2: Based on manual labelling training (Preference General)</h4>
<p><strong>Apply scene</strong>: subjective tasks (e.g. quality of dialogue, writing style)</p>
<p><strong>Training process</strong>：</p>
<pre><code class="language-python"># 示例：人工偏好数据
training_data = [
    {
        &quot;prompt&quot;: &quot;写一首关于春天的诗&quot;,

</code></pre>
<p><strong>Rationale</strong>：</p>
<ul>
<li>Manual tabifier compares two responses</li>
<li>Incentive models to learn to predict human preferences</li>
<li>After training, model outputs match human judgment.</li>
</ul>
<p><strong>Advantages</strong>：</p>
<ul>
<li>[Effects] Capture complex quality dimensions: fluidity, creativity, utility</li>
<li>[Effects] Broader capacity: various tasks can be addressed</li>
</ul>
<p><strong>Limits</strong>：</p>
<ul>
<li>[Facilitation] High cost</li>
<li>[Facilitative] Subjectivity: Different labelers may not be consistent</li>
</ul>

<pre><code class="language-python">def hybrid_reward(rule_score, judge_score, cost, has_hard_violation):

</ul>

<h4>3.5.2 Incentive model structure</h4>
<p>Neuro-reward models usually add headers to the pre-trained language model, allowing them to export a standard incentive, which is fine-tuned with the incentive data collected. The following is a toy-level example to illustrate the structure, which does not represent the achievement of the only or standard RM in LLM RLHF/ RLVR.</p>
<pre><code class="language-python">import torch
import torch.nn as nn
from transformers import AutoModel

class RewardModel(nn.Module):
    &quot;&quot;&quot;
    简单的奖励模型实现
    &quot;&quot;&quot;
    def __init__(self, base_model_name=&quot;bert-base-uncased&quot;):
        super().__init__()
        self.encoder = AutoModel.from_pretrained(base_model_name)
        hidden_size = self.encoder.config.hidden_size

        # 奖励头：输出单个标量
        self.reward_head = nn.Sequential(
            nn.Linear(hidden_size, hidden_size // 2),
            nn.ReLU(),
            nn.Dropout(0.1),
            nn.Linear(hidden_size // 2, 1)
        )

    def forward(self, input_ids, attention_mask):
        # 编码
        outputs = self.encoder(
            input_ids=input_ids,
            attention_mask=attention_mask
        )

        # 使用 [CLS] token 的表示
        cls_embedding = outputs.last_hidden_state[:, 0, :]

        # 计算奖励
        reward = self.reward_head(cls_embedding).squeeze(-1)

        return reward

# 训练循环
def train_reward_model(model, training_data, epochs=3):
    optimizer = torch.optim.AdamW(model.parameters(), lr=1e-5)
    loss_fn = nn.MSELoss()  # 回归损失

    for epoch in range(epochs):
        for batch in training_data:
            prompts = batch[&quot;prompt&quot;]
            responses = batch[&quot;response&quot;]
            targets = batch[&quot;reward&quot;]

            # 前向传播
            rewards = model(prompts, responses)

            # 计算损失
            loss = loss_fn(rewards, targets)

            # 反向传播
            loss.backward()
            optimizer.step()
            optimizer.zero_grad()

    return model
</code></pre>

<h3>A unified paradigm and insight for enhanced learning and training</h3>
<p>Based on the original GRPO paper, we can understand the interlinkages and differences in the various methods of intensive learning training from a more macro-level perspective.</p>
<h4>A unified and enhanced learning and training framework</h4>
<p>The GRPO paper proposed a unified framework for intensive learning training that incorporated different training methods (SFT, RFT, DPO, PPO, GRPO, etc.) into the same analytical framework.</p>
<p><strong>Core Gradient Formula</strong>：</p>
<p>&#36;&#36;
\nabla_\theta J_\pi(\theta) = \mathbb{E}<em>{(q, o) \sim \mathcal{D&#125;&#125; \left[ \frac{1}{\lvert o \rvert} \sum</em>{t=1}^{\lvert o \rvert} GC_\pi(q, o, t, \pi_f) \nabla_\theta \log \pi_\theta(o_t \mid q, o_{&lt;t}) \right]
&#36;&#36;</p>
<p>Of which:</p>
<ul>
<li>&#36;q&#36;: Query or hint</li>
<li>&#36;o&#36;:output or response</li>
<li>&#36;t&#36;Time steps</li>
<li>&#36;\pi_f&#36;: Reference policy or incentive function for assessing quality</li>
<li>&#36;GC_\pi&#36;Gradient Coefficent, determining the direction and range of the updated parameters</li>
</ul>
<p><strong>Three key components</strong>：</p>
<ol>
<li><strong>Data Sources &#36;\mathcal{D}&#36;</strong>: source of training data</li>
<li><strong>Incentive Functions &#36;r_{\pi_f}&#36;</strong>: provide training incentive signals</li>
<li><strong>Algebra &#36;\mathcal{A}&#36;</strong>: processing data and reward signals, generating gradient coefficients &#36;GC&#36;</li>
</ol>
<h4>Classification of different training methods</h4>
<p>Based on this unified framework, we can group common training methods into several categories:</p>
<h4>Offline Methods</h4>
<p><strong>RFT（Rejection Sampling Fine-tuning）</strong>：</p>
<ul>
<li>SFT-based sample output</li>
<li>Filter based on correctness of answer</li>
<li>Just fine-tune the right response.</li>
<li>Feature: Simple and effective, but unable to use information that responds to a mistake</li>
</ul>
<p><strong>DPO（Direct Preference Optimization）</strong>：</p>
<ul>
<li>Use as a pair of preferences to optimize loss</li>
<li>fine-tune on enhanced outputs</li>
<li>No need for a visible reward model</li>
<li>Feature: Stable and efficient, suitable for subjective preference</li>
</ul>
<h4>Online Methods</h4>
<p><strong>Online RFT</strong>：</p>
<ul>
<li>Initializing policy model with SFT model</li>
<li>fine-tuning using enhanced output from real-time policy models</li>
<li>Online sampling to explore new responses</li>
<li>Feature: Early training is comparable to RFT and later is significantly better than RFT</li>
</ul>
<p><strong>PPO/GRPO</strong>：</p>
<ul>
<li>Initializing policy model with SFT model</li>
<li>Enhanced output policy through real-time strategy models</li>
<li>Use gradient factor for variance update</li>
<li>Feature: Performance in relevant experimental settings is strong, especially in the case of GRPOs, which achieves a good balance between efficiency and effectiveness</li>
</ul>
<h4>Core Insight: Online vs offline</h4>
<h4>Differences in training dynamics</h4>
<p><strong>Initial phase</strong>：</p>
<ul>
<li>Actor (tactical model) is similar to SFT</li>
<li>Small differences in sampling data</li>
<li>The advantages of online methods are not clear.</li>
</ul>
<p><strong>Later</strong>：</p>
<ul>
<li>Actor sample data and SFT data are significantly increasing</li>
<li><strong>The advantages of online sampling have become obvious.</strong></li>
<li>Real-time data exploration has brought about more significant performance improvements.</li>
</ul>
<h4>Performance Comparison</h4>
<p>In the DeepSeekMath 1.3B GSM8K/MATH Experimental Set, several training developments were reported:</p>
<ul>
<li>Online RFT has significantly outperformed RFT in the advanced stages of training.</li>
<li>GRPO exceeded Online RFT in two baseline tests</li>
<li><strong>The iterative RL was the most significant increase in the first round.</strong></li>
<li>GRPO + PS (step gradient factor) is better than GRPO + OS</li>
</ul>
